# Status

Project decisions and the current state of the replication. Read this before changing the experiments;
add new instructions here when they are given.

## Instructions

- **Only public datasets.** The replication uses CoverType and Higgs (OpenML). The paper's telecom
  datasets are out: VoD, Sim-A and Sim-B are Ericsson-internal, and their configs were removed.
  DeepMIMO is public but has to be generated by hand; its config is kept, but it is not part of the
  sweeps unless that is decided.
- **Only prediction performance and model size matter, not search time.** Table III (search time),
  Fig. 2 (performance vs. search time) and the speed-up headline numbers are not reproduced. Timings
  are still written to the result JSONs but nothing reads them, so runs may share the CPU.
- **Figures 4 and 5 run on CoverType**, since the paper's VoD dataset is not available.
- **Run on the CPU, several runs in parallel.** See "Findings" for why not MPS.
- **Do not open PRs to the upstream repository** (from AGENTS.md).

## Findings (M1 Pro, 6+2 cores, 16 GB, torch 2.5.1)

- **CPU beats MPS by 2–7×** on every component at batch size 256: the MLPs are too small for the GPU,
  and per-step kernel launches and `.item()` syncs dominate. TabNAS is worst, since every sampled width
  is a new shape that MPS compiles again.
- **TabGNS is broken on MPS:** fine-tuning a model with a zero-width layer crashes
  ("Placeholder tensor is empty"), and a search on CoverType-sized data produced NaN gate logits.
- **One run barely uses more than one thread** (6 threads are ~15% faster than 1). Six to eight
  single-threaded runs side by side give ~3.5× the throughput of one 6-thread run, hence
  `hydra/launcher=joblib hydra.launcher.n_jobs=6 threads=1`.
- **AgE:** 20 workers are no faster than 8 on this machine; use `method.n_workers=8`.
- **Epochs until early stopping** on a 50k-row CoverType subsample: Large MLP ~60, TabGNS search
  ~130–150 + fine-tune ~23, TabNAS search ~270–300 (it rarely stops early) + retrain ~85.

## Exploration: TabGNS on TabM (`experiments/tabm_gns/`, results in `results/tabm_gns/`)

Goal (user, 2026-11-08): transfer TabGNS to the TabM architecture, test it on three public datasets,
keep the results in a dedicated folder, open a PR with the findings. Details and results in
`experiments/tabm_gns/REPORT.md`.

Decisions:
- **Datasets:** California (OpenML 44025, regression), Adult (1590, binary), Otto (45548, 9 classes):
  all in the TabM benchmark, none used by the replication. 3 seeds, 60/20/20 splits, preprocessing
  fitted on train only.
- **TabM:** own re-implementation of `tabm` 0.0.3's `arch_type='tabm'` (parity unit test), defaults
  3 × 512, k = 32, dropout 0.1, AdamW lr 2e-3 / wd 3e-4.
- **Gates are shared by all k members** (pruning a neuron removes a row of the shared W). Two noise
  variants: one mask per pass (`tabm_gns`) and one mask per member (`tabm_gns_member`).
- **TabGNS itself is unchanged**, quirks included (P(open) = sigmoid(g − 1) while sampling, last-epoch
  checkpoint).
- **Controls** (asked for by the user, 2026-11-09): rewind (found widths with the supernet's initial
  weights, same seeds), scratch (fresh init), uniform (equal widths, same parameter count).
- **Datasets are read from OpenML's ARFF, not parquet** (`OPENML_SKIP_PARQUET`): the venv's pyarrow
  cannot read parquet, and OpenML only started serving parquet for these datasets mid-study.
- **Time limit** (user, 2026-11-09): processing had to end by 19:00, so the Otto rewind replays
  (~6–10 h) were deferred to `experiments/tabm_gns/queue_deferred.txt`.

Findings:
- TabGNS-TabM matches Large TabM at 3.5–41% of its parameters (better RMSE on California at ~20%,
  −0.1/−0.2 pp accuracy on Adult at ~4%, equal on Otto at 32–41%).
- It compresses TabM far less than an MLP (0.9–1.9% there); the found size grows with k.
- On California and Adult, rewind, scratch and uniform retrainings are as good as the warm-started
  model: TabGNS works as a size selector, the weights and the uneven shape add nothing. On Otto the
  warm start is ~1 pp better than scratch and uniform; the rewind control that would tell init from
  training is deferred.
